아키텍처 문제(계층 위반 · 순환 의존 등)는 결함과 나눠 **개선 제안**으로 적는다. 재현되지 않은 의심은 **미확인**으로 따로 둔다.

## 2. 환경 — 외부 호출 · 실제 데이터 보호

1. **QA 스택(주 검증 환경)**: 별도 compose 프로젝트 `roadrail-qa` — 자체 PostgreSQL · Redis(다른 포트), DB 는 개발 DB 를 `pg_dump` 로 떠서 복원.
   API · 웹은 **외부 API 키를 모두 비운 채**(카카오 · 기상청 · TAGO 등 호출 0) 실행, 관리 토큰은 시험용 값. 장애 주입(DB · Redis 멈춤 · 재시작) · 부하 · 비정상 입력은 여기서만.
2. **개발 스택(localhost:3300 · 8300)**: 읽기 위주의 화면 확인(지도 · 실제 응답)만, 캐시된 조합으로 몇 번만. 반복 · 부하 · 장애 주입 없음.
3. **시험 프레임워크**: API 는 Testcontainers(목 HTTP), 수집기는 compose 시험 DB + 가짜 전송(httpx MockTransport) — 외부 응답은 저장된 fixture · 목.
4. 운영 환경 · 실제 계정은 없다(로컬 서비스). 실제 키가 필요한 검증은 하지 않는다.

## 3. 위험 순서대로 — 무엇을 어떻게

### P0 보안
- **인증 · 인가**: 관리 API(토큰 없음 · 틀림 · 빈 값 · 대소문자 · 아주 긴 값 · 다른 경로 표기 `%2F` · `;`), 토큰 비교의 시간 차이, 관리 경로 요청 한도. 수집 상태의 오류 상세(공개 엔드포인트)에 민감 정보가 나오는지.
- **ID 조작**: 사용자 계정이 없는 서비스라 '남의 데이터'는 없다 — 대신 경로 · 쿼리의 ID(`{id}` · `dep/arr` · `job`)를 바꿔 내부 정보 · 다른 작업에 닿는지.
- **인젝션**: 모든 문자열 매개변수(`q` · `sort` · `groupBy` · `agg` · `dir` · `corridorId` · `date` · 백필 본문)에 SQL 메타문자 · 와일드카드(`%` `_`) · 유니코드 · NUL · 아주 긴 값. Redis 키 · 로그 주입(개행).
- **XSS · CSRF · 헤더**: 응답에 되돌아오는 이름(`fromName` 등)이 화면에서 HTML 로 해석되는지, 모든 경로(웹 페이지 · API · 프록시 · 404 · 오류 응답 · Swagger)의 보안 헤더 · CSP, CORS 허용 범위, 상태를 바꾸는 요청(POST)의 CSRF 가능성(쿠키 인증 여부).
- **비밀값**: 저장소 전체 이력(gitleaks) · 컨테이너 로그 · 오류 응답 · 수집 상태 응답 · 웹 번들(`NEXT_PUBLIC_*` 외 키)에서 키 패턴 검색.
- **버전 · 취약점**: npm audit · pip-audit · GitHub Dependabot · CodeQL 경보, 런타임 · 프레임워크 지원 종료일.

### P0 데이터 손실 · 신뢰성
- 수집 작업이 도중에 끊기거나 재시작될 때(잠금 · 예약 · 커서 · 실행 기록), 같은 작업 동시 실행, 관리 명령 동시 요청(작업 실행 · 백필 중복 등록).
- QA 스택에서 DB · Redis 를 멈춤 · 지연시킬 때 API 응답(500 대신 503 · 회복), 캐시 오염 여부.
- 외부 API 가 느리거나 끊길 때(목) — 판단 카드 pending · 캐시하지 않음 · 예산 회계.
- 마이그레이션을 빈 DB · 기존 DB 에 적용(Flyway) · 보존 기간 정리 경계.

### P1 기능 정확성
- **API 퍼즈 매트릭스** (`qa/api_matrix.py`, 표준 라이브러리): 19개 경로 × 정상 · 경계 · 비정상 값(아주 큰 수 · 음수 · 0 · NaN/Infinity · 잘못된 날짜 · 뒤바뀐 기간 · 빈 값 · 1만 자 · 조작 문자열). 기대: 정상은 2xx, 잘못된 입력은 **400 JSON(`code · message · traceId`)**, **5xx · HTML · 스택 트레이스 0**, 응답 시간 상한.
- 계산 규칙: 판단 규칙 · 정시율 경계(임계값 · 확인 불가) · 날짜 경계(자정 · 공휴일) — 기존 단위 테스트 범위 밖만 표본 확인.

### P1 화면 · UI/UX
- **Playwright 순회** (`web/e2e/qa-crawl.spec.ts`): 모든 메뉴에서 버튼 · 탭(세그먼트) · 선택 상자 · 검색 · 표 펼치기를 누르고 **콘솔 오류 · 실패한 요청(4xx/5xx · 네트워크 실패) · 중복 요청(같은 주소 1초 안 2번)** 수집. 데스크톱 1440 · 모바일 375(가로 넘침), 키보드만으로 조작(Tab 순서 · 초점 표시 · Enter/Esc).

### P2 성능
- **부하** (k6, QA 스택 — 외부 호출 없음): 핵심 API(판단 카드 캐시 적중 · 길 판단 카드 · 정시율 · 날짜별 운행 · 역 검색 · 시계열 · 수집 상태)에 동시 10 · 50 사용자, 각 30초 → p50 · p95 · p99 · 처리량 · 오류율.
- 느린 쿼리(`log_min_duration_statement` — QA DB 에서만) · `EXPLAIN ANALYZE`, 지나치게 큰 응답(바이트).
- 화면: Lighthouse(성능 · 접근성 · 모범 사례) — 주요 페이지 데스크톱 · 모바일.

### P2 접근성 (WCAG 2.1 AA)
- Lighthouse 접근성(axe 규칙) + 키보드 조작 · 초점 · 대비 · 이름 없는 컨트롤 · 랜드마크. 위반을 기준 항목별로 정리.

### 회귀
- 기존 테스트 전체(collector · API · 웹 단위 · E2E) 실행, **중요한데 테스트가 없는 경로** 목록.

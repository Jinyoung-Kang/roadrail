# ADR-016 추정 대신 실제 값 — TAGO 열차 시간표 채택과 추정치 정리

- 상태: 채택 (2026-09-25)
- 배경: 열차 종류를 번호 범위로 짐작(T-v1)해 '추정'이라 표시해 왔다. 사용자 지적으로 검증해 보니 틀린 값이 있었다
  (01501 → 규칙은 무궁화호, 실제는 ITX-마음). 같은 기준으로 전 메뉴를 점검했다([DATA-PROVENANCE](../DATA-PROVENANCE.md)).

## 결정

1. **원칙** — 화면에는 공식 값 · 그 값의 통계 · 밝힌 예측만. 대체할 실제 값이 없으면 지운다. 남기는 추정은 이유와 함께 문서화하고 화면에 밝힌다.
2. **TAGO 열차정보 `GetStrtpntAlocFndTrainInfo`** — 역 쌍 · 날짜별로 열차 번호 · 출발역 계획 출발 · 도착역 계획 도착 · 그날 배정 차종.
   - 실측: 지난 날짜는 전체 시간표(서울→대전 09-18 130편), 당일 일부 · 미래 0편, 열차 번호 형식은 코레일과 같음(00201).
   - 역 ID: 시도별 역 목록(16건)으로 이름 매칭 — 코레일 운행 역 276곳 중 273곳 일치. `여수엑스포 = 여수EXPO` 는 열차 번호 · 시각이 모두 일치해 별칭으로 등록(검증한 것만). 평택지제 · 덕정은 TAGO 에 없음.
   - 저장: `rail.tt_plan`(V11) · 조회 기록 `rail.tt_fetch`. API 가 역 쌍 · 날짜를 처음 볼 때 한 번 받는다(동시 요청은 한 번으로 합침, 최대 6건 병렬 · 초당 10건 · 429 는 1~2초 뒤 재시도).
   - 불완전한 날: 받은 편수가 코레일 운행 편수의 80% 미만이면 `complete=false` 로 두고 12시간 뒤 다시(V12). 실측 09-21 0편 · 09-23 1편.
3. **정시성** — `rail.od_trips` 가 출발역 · 도착역 각각 EXACT(운행계획) → TT(TAGO) → EST(보간) 순으로 계획 시각을 고른다.
   화면 통계는 `rail.od_trips_real`(V13)로 **EXACT · TT 만** 쓰고 EST 는 확인 불가로 뺀다. 보간은 환승 탐색 내부에만 남는다.
4. **여정** — CSA 로 찾은 구간의 시각을 기준일 실제 시간표로 바꾸고 승차 여유 · 최소 환승을 다시 확인, 안 되면 그 여정을 뺀다.
5. **그 밖 정리** — 역까지 직선거리 추정 → 카카오 개별 경로(못 얻으면 제외) · 도로 '국도/도시고속' 이름 분류 → 고속도로 / 그 외 도로 · 카카오 통행료(0원) 비표시 · 돌발 위치는 응답 좌표가 있을 때만.

## 결과 (실측)

- 서울→대전 30일(08-26~09-24): 보간 기준 정시율 89.7% → **시간표 비교 83.9%**(확인 3,257 · 확인 불가 347). 보간이 지연을 과소 추정한다는 기존 관찰(VERIFICATION 한계)을 수치로 확인.
- 9/22 서울→대전 114편 모두 차종 · 계획 시각 확인(KTX 51 · KTX-산천 36 · ITX-새마을 12 · 무궁화호 11 · ITX-마음 3 · KTX-청룡 1).
- 처음 보는 역 쌍의 30일 시간표: 약 30건 · 2~3초(2.5초까지 기다리고 나머지는 화면이 다시 불러 채움).

## 한계

- TAGO 가 비어 있는 날의 중간역 운행은 통계에서 빠진다(표본 감소 — 화면에 확인 불가 수 표시).
- 앞으로의 시간표는 어디에도 없어 최근 같은 요일의 실제 시간표를 쓴다(남긴 추정).

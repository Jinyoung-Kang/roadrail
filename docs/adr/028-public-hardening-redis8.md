# ADR-028 공개 배포 보호 — 수집 상태 오류 상세는 관리 토큰 뒤로 · API 문서 기본 끔 · Redis 비밀번호 · Redis 8

- 상태: 채택 (2026-10-05)
- 배경: README 의 공개 배포 체크리스트(ADR-018)와 QA 보고서 개선 1 · 6절. 모든 포트가 127.0.0.1 에만 열린 로컬 서비스라 수집 상태의
  오류 상세(스택 트레이스 · 외부 호출 — 키는 마스킹) · Swagger · 비밀번호 없는 Redis 를 열어 두었다. 사용자 결정(2026-10-05)으로 셋을 닫고,
  상용판 지원 종료(2026-11-30)가 다가온 Redis 7.4 를 8 로 올린다.
- 원칙: 이미 있는 장치(관리 토큰 검사 · 관리 요청 한도 · .env · make env)를 다시 쓴다. 공개 화면의 쓸모(작업 상태 · 완전성 · 예산)는 그대로 둔다.

## 결정

1. **수집 상태는 두 경로.** `GET /ops/collect-status`(공개)는 실패 · 부분 성공 · 예산 부족 실행의 메시지 · 스택 트레이스, 외부 호출 오류의
   주소 · 문구를 비우고 `detailed: false`. 정상 실행의 작업 메모(예: "UTIC 돌발 62건")와 상태 · 시각 · 건수는 남긴다.
   전체는 `GET /admin/collect-status`(`detailed: true`) — `/admin/**` 의 관리 토큰 검사(상수 시간 비교 · 401)와 관리 요청 한도를 그대로 쓴다.
   - 하지 않은 것: 같은 경로에서 머리글 유무로 응답을 바꾸기 — 캐시 · `Vary` 를 따로 챙겨야 하고, 틀린 토큰의 대입을 막을 한도를 새로 둬야 한다.
   - 화면: 공개 응답은 늘 받고, 관리 토큰이 있으면(입력이 0.6초 멈춘 뒤) 관리 경로에서 상세를 받아 겹친다. 틀린 토큰이어도 화면은 공개 응답으로 그대로.
2. **API 문서는 기본으로 끈다.** springdoc `swagger-ui` · `api-docs` 의 `enabled` 를 `${SWAGGER_ENABLED:false}`. 웹은 같은 값을 빌드 인자
   `NEXT_PUBLIC_API_DOCS` 로 받아, 켰을 때만 메뉴 · 꼬리말에 링크를 둔다(꺼진 문서로 가는 링크를 남기지 않게). 로컬에서는 `.env` 에 `SWAGGER_ENABLED=true`.
3. **Redis 비밀번호.** `.env` 의 `REDIS_PASSWORD`(`make env` 가 `openssl rand -hex 24` 로 만든다 — 영문 · 숫자라 주소에 그대로 넣을 수 있다).
   - 값은 환경 변수로 넘기고 셸에서 `--requirepass "$REDIS_PASSWORD"` — `docker inspect` 의 명령줄에 값이 남지 않는다. 비어 있으면 Redis 가 기동하지 않는다.
   - 셸로 감싸도 공식 진입 스크립트(`docker-entrypoint.sh`)를 거쳐 redis 사용자로 권한을 낮춘다(감싸기만 하면 root 로 돈다). 헬스 검사는 `REDISCLI_AUTH`.
   - api 는 `SPRING_DATA_REDIS_PASSWORD`, 수집기는 설정 `redis_password`(주소에 비밀번호가 있으면 주소가 우선 — 시험용 주소), 로그 마스킹 대상에 넣는다.
   - compose 에서 필수 변수(`:?`)로 두지 않는다 — CI 는 `.env.example` 로 `docker compose build` 만 한다. 필수 여부는 Redis 기동 시점에 검사.
4. **Redis 8**(`redis:8-alpine`, 8.10.2). 개발 · QA 스택, CI 서비스, Testcontainers 모두. 키 규약 · Lua(예산) · 스트림 · 잠금은 그대로.
   Redis 8 오픈소스는 RSALv2 · SSPLv1 · AGPLv3 중 고르는 삼중 라이선스다 — 공식 이미지를 수정 없이 내부 캐시로만 쓰고 서비스로 제공하지 않아
   이 프로젝트에 의무가 생기지 않는다. 영속화를 끈 캐시라 데이터 이전은 없다(예산 확정값은 `ops.quota_budget` 에서 복원).
   - 대안 Valkey(BSD)는 이번에 고르지 않았다 — 사용자가 Redis 업그레이드를 요청했고, 지금 쓰는 기능은 둘 다 같아 나중에도 이미지만 바꾸면 된다.
5. **`maxmemory` 는 아직 걸지 않는다.** 예산 카운터 · 작업 잠금도 만료(2일 · 잠금 TTL)가 있어 `volatile-*` · `allkeys-*` 정책 모두 메모리가 찰 때
   캐시와 함께 밀어낼 수 있다(예산이 밀려나면 다음 동기화까지 그날 사용량을 모른다). `noeviction` 은 캐시 쓰기가 실패한다.
   캐시를 다른 DB 번호로 나누거나 캐시 키만 만료를 두는 정리 뒤에 건다 — 체크리스트에 남긴다.

## 결과

- 시험: API 132(공개 응답은 상세 null · 관리 경로 토큰 없음/틀림 401 · 맞으면 스택 트레이스 · 문서 경로 404), collector 127(Redis 8 · 비밀번호),
  웹 단위 35, E2E 43(공개 응답 · 401 · 관리 토큰으로 상세와 복사 포함).
- 개발 스택: Redis 8.10.2, 인증 없으면 `NOAUTH` · 틀리면 `WRONGPASS`, 프로세스는 redis 사용자, 헬스 UP, 공개 응답 상세 0건 · 관리 응답 8건, `/docs` 404.
- `make env` 가 끝에 줄바꿈이 없는 `.env` 에 키를 덧붙이며 마지막 줄 값 뒤에 붙이던 것을 이번에 실측해 고쳤다(먼저 줄바꿈을 넣는다).

# ADR-023 기능 고도화 — 자동차 경로 구간별 소통(지도 색) · 초단기 날씨 · 경찰청 UTIC 돌발 · 보유 API 검토

- 상태: 채택 (2026-09-28) · 같은 날 UTIC 돌발 연동(결정 5)
- 배경: 보유한 API 키 목록(공공데이터포털 · 한국도로공사 · 카카오 · 경찰청 UTIC 등)으로 **새 기능이 아니라 기존 기능을 보강**할 방법을 찾았다.
  요구: 자동차 지도(판단 · 도로 분석)에서 정체 · 사고 구간을 다른 색으로. 아키텍처 · 성능 · 보안을 함께 본다.

## 결정

1. **자동차 경로의 구간별 소통 — 새 키 없이.** 이미 받는 카카오 길찾기 응답의 `roads[].traffic_state` · `vertexes` 를 지도까지 보낸다.
   - 서버(`domain/RouteGeometry`): 소통이 같은 도로를 한 구간으로 합치고 구간마다 Douglas–Peucker 로 줄인다. 점별 DP 중요도
     (부모 분할점 값으로 상한 — 부모가 버려지면 자식은 검사되지도 않는다)를 한 번만 계산해, 400점 상한에 맞는 허용 오차를 바로 정한다.
     구간 경계는 늘 남고 이웃 구간이 경계 점을 함께 쓴다. 응답: `path`(≤ 400점) + `traffic[{from, to, traffic, distanceM}]`.
     예전 균등 추출(400점)은 구간 경계가 사라져 색을 나눌 수 없고 굽은 길을 깎았다.
   - 실측: 서울역 → 대전역 25구간 · 400점 · 구간 길이 합 164.8km = 경로 거리. 서울역 → 부산역 25구간 · 405.6km.
   - 화면: 지체 `#c93a8c` · 정체 `#9c1033` · 사고 `#6b35a3`(점선)을 흰 테두리 위에 덧그린다. 판단 지도에는 기차 주황 · 자동차 파랑이 함께
     있어 다섯 색을 dataviz 로 검증했다(모든 쌍: 색각 이상 ΔE ≥ 9.3 · 정상 시각 ≥ 16.2 · 표면 대비 ≥ 3:1). 흔한 노랑 · 빨강은 기차 주황과
     정상 시각 ΔE 10.8, 황갈은 색각 이상 ΔE 약 2 로 탈락했다. 색만으로 구분하지 않게 범례 글자 · 사고 점선을 둔다.
     서행은 기본색 — 서버의 '느린 구간'(지체 · 정체 · 사고) 기준과 같게. 자동차 카드에는 길이 비율의 '경로 소통' 띠와 요약.
   - 캐시 형식이 바뀌어 키를 바꿨다(`kakao:etap2` · `kakao:route2`) — 20분 동안 예전 형식과 섞이지 않게.
2. **'느린 구간' 결함 수정(검증 기록 73).** 같은 이름의 도로를 합치며 가장 나쁜 소통을 전체 길이에 붙여 '경부고속도로 정체 152.5km'
   (실제 6.8km)로 보였다. 느린 구간은 이름과 소통이 모두 같을 때만 합치고, 도로 구성 표는 가장 나쁜 소통에 그 길이(`trafficM`)를 붙인다.
3. **초단기 날씨 — 같은 서비스, 같은 키.** 공공데이터포털 `VilageFcstInfoService_2.0` 의 초단기예보(매시 30분 발표 · 6시간 앞)와
   초단기실황(매시 정각 관측)을 쓴다(실제 호출로 확인).
   - 출발이 5시간 안이면 초단기예보로 기온 · 하늘 · 강수형태 · 1시간 강수량을 덮는다. 강수확률은 단기예보에만 있어 그대로.
     지금 출발(±20분)이면 실황 관측으로 덮는다. 근거는 `weatherSource`(예: "초단기실황 16:00 관측")로 날씨 카드 · 데이터 시각에 보인다.
   - 판단 규칙: 출발 시각의 강수형태가 비 · 눈이면 강수확률이 기준(60%)보다 낮아도 경고한다. 강수확률 경고와는 하나만.
   - 결함 수정(검증 기록 74): 단기예보 새 발표는 발표 +1시간부터라, 발표 직후 한 시간은 '지금 출발' 날씨가 모두 비었다 → 직전 발표에서 읽는다.
   - 비용: 격자 · 발표마다 1회(75분 캐시, 같은 키 동시 요청은 한 번), 세 조회를 가상 스레드로 동시에. 오류 응답(`resultCode ≠ 00`)은 캐시하지 않는다.
     KMA 일일 예산(9,000) 안에서 새 격자당 시간에 최대 2건 늘어난다.
4. **보유 API 검토**

   | API | 판단 |
   |---|---|
   | 경찰청 UTIC 돌발정보 | **연동(결정 5)** — 전국 사고 · 공사 · 행사 · 통제(일반 도로 포함). 전에는 도로공사 문자라 고속도로만 |
   | UTIC 소통정보 | 보류 — 표준 링크 단위 속도라 노드 · 링크 좌표가 따로 필요. 경로 위 소통은 카카오로 충분 |
   | 기상청 중기예보 | 보류 — 판단은 몇 시간 안의 출발 |
   | 기상청 API 허브 | 불필요 — 같은 초단기 자료를 공공데이터포털 키로 받는다 |
   | 한국도로공사(보유 키) | 이미 사용 — 영업소 통행시간 · 교통량 · 돌발 문자 |
   | 서울시 노선정보 | ADR-019 대로 쓰지 않음 |
   | SGIS · V-World · KOSIS · 법정동코드 | 불필요 — 좌표 → 행정구역은 카카오로 이미 |
   | 부동산원 · 실거래가 · DART · 주식 · 의약품 · 병의원 · 우체국 · 해양 · OpenSky · aisstream | 서비스 범위 밖 |

5. **경찰청 UTIC 돌발정보 — 판단 카드의 '경로 주변 돌발'을 일반 도로까지.** 키 `UTIC_API_KEY`(없으면 호출 없이 건너뜀).
   - 수집: `utic_incident` 5분마다 1회 — 한 번에 전국의 진행 중 목록(실측 65–79건). 예산 1,000/일(쓰는 양 288).
     HTTPS 만(HTTP 로는 다른 응답이 온다 — 실측) · 응답 5MB 상한 · XML 은 표준 라이브러리 expat(외부 엔터티를 읽지 않는다).
     키는 호출 로그에 `***` 로만 남는다(실제 수집 뒤 DB · 로그에서 키 원문 0건 확인). 틀리거나 만료된 키는 HTTP 200 + JSON 오류 본문
     (`resultCode` 02 '유효한 KEY값이 아닙니다')으로 와서, 'XML 아님'이 아니라 기관의 오류 코드 · 문구로 남기고 재시도하지 않는다(검증 기록 77).
     `make smoke` 도 UTIC 키를 확인한다(키가 있을 때만 · 출력은 마스킹).
   - 저장: 같은 표 `ts.road_incident` 에 `source`(EX · UTIC) · `end_at`(종료 예정) · `lane`(통제 차로)을 더했다(V16 — 상수 기본값
     열 추가라 표를 다시 쓰지 않고, 기존 행은 EX). 행 키는 `sha256("UTIC:" + incidentId)` — 다시 보이면 내용과 `last_seen_at` 만
     갱신하는 멱등 upsert 라, '지금 안내 중'(20분 안에 다시 보임) 기준을 도로공사 문자와 함께 쓴다.
   - 해석: 좌표는 WGS84(`locationDataX` = 경도), 대한민국 밖이면 위치 없음(추정하지 않음). 시각은 '2026년 09월 28일  17시 30분'(KST),
     형식이 깨진 행은 버린다. 유형 코드 1 · 2 · 5 는 실제 제목 머리([사고] · [공사] · [통제])로 확인했고 모르는 코드는 제목 머리를 쓴다.
     도로명 앞뒤에 입력자가 붙인 기호('*관문대로,' — 실측)는 걷어 낸다(본문은 그대로).
   - 경로 위 판단(검증 기록 75): 도로공사 문자는 경로에서 2km, UTIC 는 0.5km 안. 2km 로는 서울 도심에서 나란한 다른 길(강변북로 ·
     올림픽로 · 성북로)의 사고가 섞였다. 좌표 있는 도로공사 안내 0.5km 안의 UTIC 건은 같은 돌발로 보고 도로공사 것 하나만 남긴다
     (고속도로는 도로공사 문자가 공식 안내 — 실측: UTIC '중부내륙고속도로 사고' = 도로공사 '중부내륙선 고장').
   - 건수(검증 기록 76): 판단 경고의 건수는 전체, 응답 목록은 최근 20건(`incidentTotal` 에 전체 건수). 화면은 5건만 펼치고 나머지는 버튼으로.
   - 길 화면의 돌발 목록(`/incidents`)은 도로공사 문자만 — 길 매칭(M-v1)이 고속도로 노선 기준이다.
   - 화면: 항목마다 출처(도로공사 · 경찰청 UTIC). 시각은 출처의 뜻대로 — 문자는 '발송', UTIC 는 '시작 · 종료 예정'과 통제 차로.
     UTIC 의 위치는 구간이 아니라 주소라 '위치'로 적는다. 지도 범례에 출처별 건수.

## 결과

- 테스트: JUnit 단위 +19(82) — 좌표 줄이기 · 경계 공유 · 400점 상한 · 카카오 응답 해석 · 초단기 발표 시각 · 날씨 합치기 · 강수형태 경고.
  E2E +1(20) — 실제 카카오 응답에서 구간이 경로 전체를 빈틈없이 덮는지 · 길이 합 · 범례.
- UTIC 테스트: collector 계약 +2(12) — 실제 응답 fixture(사고 · 공사 · 통제 + 경계 4건) · 시각 형식. 통합 +3(27) — 멱등 upsert ·
  출처 · HTTPS · 호출 로그 키 마스킹, 키 오류 응답은 기관 코드로 · 재시도 안 함, 키 없으면 호출 안 함. JUnit 단위 +2(84) — 겹침 제거 · 도심 돌발은 경로 위만.
  API 통합 +2(19) — 길 돌발 목록은 도로공사 문자만 · 경로 위 25건 전부 최근 순(출처별 거리 · 겹침 · 끝난 돌발 제외).
  E2E +1(21) — 화면이 받은 응답의 UTIC 건이 모두 0.5km 안 · 경고 건수 = 전체 · 펼친 목록 = 응답 · 출처 표시.
- 실측(연동 직후): 서울역→부산역 8건(도로공사 2 · UTIC 6, UTIC 모두 0.3km 안) · 서울역→대전역 10건(도로공사 6 · UTIC 4).
- 한계: 소통은 카카오 '미래 운행 정보'(출발 시각 기준 예측)다. 같은 돌발이라도 도로공사 문자에 좌표가 없으면 UTIC 건과 비교할 수 없어
  두 건으로 보일 수 있다. UTIC 응답은 지금 진행 중인 목록뿐이라 끝난 돌발은 마지막으로 본 시각(`last_seen_at`)까지만 남는다.

# ADR-024 코드 리뷰 (2026-10-04) — 수집 신뢰성 · 요청 한도 · 웹 조회 상태를 React 밖으로

- 상태: 채택 (2026-10-04)
- 배경: 전체 코드 리뷰([보고서 · 계획](../review/2026-10-04-review-and-plan.md))에서 High 1 · Medium 12 · Low 26 을 찾았다.
  우선순위는 보안 · 데이터 손실 → 정확성 → 아키텍처 → 성능. 이 문서는 PR 1(`fix/review-2026-10-04`)에서 내린 설계 결정과
  하지 않기로 한 것을 이유와 함께 남긴다. 각 결함의 재현 · 수치는 [검증 기록](../VERIFICATION.md) 78~95번.

## 결정

1. **도로 꼬리 커서는 원천 데이터의 날짜로 센다 (H1 · M2).** 도로공사 `realUnitTrtm` 은 자정 뒤 약 01:30 까지 전날을 계속 준다.
   벽시계 날짜를 키로 쓰면 전날 행 수가 새 날 커서가 되어 새 날 아침을 놓친다.
   - 커서 값 = `stdDate:그날 본 1종 행 수`, 키는 구간 하나. 꼬리 쪽이 다른 날이거나 비었으면 1쪽부터 — 판단은 순수 함수(`TailCursor` ·
     `tail_is_stale`)로 단위 테스트.
   - 전날 결측은 **원천이 새 날로 넘어간 뒤에만** `SOURCE_EXPIRED` 로 닫는다(1쪽 한 번으로 원천 날짜 확인). 응답이 비면 판단 보류.
2. **결측 사유는 닫힌 영역으로 (M3 · L11).** 전체를 두 번 다시 받아도 빈 슬롯은 수집 실패가 아니라 원천에 표본이 없는 것 — `NO_SAMPLES` 로
   따로 두고 더 받지 않는다(한 번으로 판단하면 원천의 일시적인 빈 응답 한 번에 영영 닫힌다 — 셀프 리뷰). 완전성 분모에서 빼고 수집 상태에 '원천 없음 N' 으로 따로 보인다(응답 필드 추가만, 기존 필드 의미 유지).
   공개 지연(약 3시간)에 4시간 여유를 두고, 모든 구간을 다시 받은 경우에만 판단한다.
   사유 · 작업 상태 · 돌발 출처 · 경위도에는 V17 CHECK — 기존 데이터를 바꾸지 않고, 적용 전 실데이터에 트랜잭션으로 먼저 걸어 보았다.
3. **호출 예산은 Redis 를 영속화하지 않고 DB 확정값으로 복원 (M1 · L3).** Redis 를 다시 띄우면 그날 카운터가 0 이 되어 한도의 두 배까지
   부를 수 있었다. AOF · 볼륨 같은 인프라 변경 대신, 기동 정리와 작업 끝마다 `ops.quota_budget`(같은 날 줄지 않는 GREATEST)과 맞춰
   적으면 한 번의 Lua 로 더한다. 예약 객체는 예약한 날짜를 기억해 자정을 넘긴 환불 · 추가 예약도 그날 키에 적는다.
   - 대안: Redis AOF — 캐시 · 잠금까지 디스크에 쓰고 운영 설정이 늘어난다. 지켜야 할 값은 예산 카운터 하나라 코드로 충분.
4. **요청 한도 버킷은 Spring 이 고른 경로 패턴으로, X-Forwarded-For 는 지정한 프록시만 (RVW-04).** 디코딩 전 URI 로 버킷을 골라
   `/api/v1/%74rip` 이 한도 밖이었다. 믿는 프록시는 루프백 + `TRUSTED_PROXIES`(기본 `web`, 1분마다 다시 풂).
   보안 헤더(프레임 금지 등)는 Next 의 rewrite 경로(Swagger)에는 붙지 않아 Spring 필터에서 모든 응답에 붙인다(WEB-10).
5. **판단 카드의 늦은 보조 조회는 '없음'이 아니라 pending (RVW-01).** 철도 계산이 시간 초과면 '열차 없음'과 같아져 "자동차만 비교"가
   60초 캐시되었다. 끝나지 않은 조회는 `pending` 으로 캐시하지 않고, 화면이 짧게 다시 부른다(상한 있음 — 6번).
6. **웹: 조회 상태 기계를 React 밖 순수 모듈로 (`lib/query.ts`).** 주소별 결과(`dataUrl` · `errorUrl`), 늦은 응답 버리기,
   '받는 중' 재시도 상한, 숨긴 탭에서 갱신 멈춤을 React 에 의존하지 않는 `createQuery` 가 맡고, `useApi` 는 얇은 훅이다.
   타이머 · 탭 가시성은 주입받아 가짜 시계로 시험한다. 같은 방식으로 지도 서명(`lib/map.ts`) · 검색 목록 규칙(`lib/picker.ts`) ·
   SDK 로더(`lib/sdkLoader.ts`)를 순수 함수로 뺐다.
   - 테스트는 **새 의존성 없이** Node 내장 테스트 러너 + 타입 제거(`npm test`). 확장자를 붙여 가져오므로 `allowImportingTsExtensions`
     (noEmit 이라 빌드 영향 없음). React 컴포넌트 테스트 도구(Testing Library · jsdom)는 들이지 않는다 — 화면 동작은 E2E 가 본다.
   - 지도는 한 번만 만들고 선 · 표식만 갈아끼운다. 범위 맞춤은 선과 일반 표식의 경계 상자가 바뀔 때만 — 돌발 표식 · 소통 색 변화로
     사용자가 옮긴 위치를 잃지 않는다.
   - 비용: 첫 로드 JS 가 페이지당 gzip 0.6~1.4KB 늘었다(같은 방법으로 main 과 비교).
7. **수집기 성능은 측정한 것만.** 같은 값 upsert 는 `IS DISTINCT FROM` 으로 건너뛰고(같은 슬롯 재수신 한 번에 갱신 3,812 → 0행),
   백테스트 · 기준선의 pandas 계산은 `asyncio.to_thread`(최대 루프 지연 16,492 → 159ms). 미해결 결측 부분 인덱스는 지금 조회가
   기존 부분 인덱스로 1.45ms 라 넣지 않았다.

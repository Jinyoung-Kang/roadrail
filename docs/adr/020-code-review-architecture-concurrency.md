# ADR-020 전체 코드 리뷰 — 의존 방향 · 동시성 · 오류 규약 · 외부 예산 몫

- 상태: 채택 (2026-09-27)
- 배경: 저장소 전체를 아키텍처 = 보안 = 성능 > 가독성 순으로 검토했다([진단 보고서](../review/2026-09-27-code-review.md)).
  발견한 결함은 모두 재현(테스트 · 스크래치 · 실제 스택)한 뒤 고치고 회귀 테스트로 고정했다.

## 결정

1. **의존 방향** — 외부 HTTP 클라이언트는 모두 `external`, 캐시 같은 인프라는 `common`, 표현 계층 DTO 는 외부 타입을 모른다.
   service ↔ external 순환과 dto → external 의존을 없앴다(클래스 이동만, 동작 불변). common ↔ config 는 인터셉터 2개가
   설정값을 읽는 구조라 남긴다.
2. **가상 스레드(JDK 21)에서 잠금 안 I/O 금지** — `ConcurrentHashMap.computeIfAbsent` 는 synchronized 라 그 안의 DB 조회가
   캐리어 스레드를 고정했다(`-Djdk.tracePinnedThreads`: `reason:MONITOR`). 메모리 캐시는 `Memo`(잠금 밖에서 한 번만 불러오고
   동시 요청은 `CompletableFuture.join` 으로 기다림 · 실패는 캐시하지 않음)로, 같은 작업 합치기는 `SingleFlight` 로 한다.
   JDK 24+(JEP 491)로 올리면 synchronized 고정 자체가 사라지지만, 그 전에도 안전한 구조를 쓴다.
3. **in-flight 합치기는 Future 를 먼저 넣고 잠금 밖에서 시작** — `computeIfAbsent(k, supplyAsync(…).whenComplete(remove))` 는
   작업이 콜백 등록 전에 끝나면 `IllegalStateException("Recursive update")` 이 나고 실패한 Future 가 맵에 영구히 남는다(재현).
4. **가상 스레드 실행기는 빈 하나** — DataSource · Redis 를 매개변수로 받아 의존 관계를 남기므로 종료 때 연결보다 먼저 닫힌다.
5. **과부하는 503** — 가상 스레드는 동시 요청 수에 상한이 없다. 연결 풀(12)이 차면 3초만 기다리고
   `503 UNAVAILABLE + Retry-After` (기본 30초 대기 후 500 이던 것).
6. **오류 규약은 표준 MVC 예외에도** — 415 `UNSUPPORTED_MEDIA_TYPE`, 406 은 본문 없이, 그 밖의 4xx 는 그 상태 코드로.
   클라이언트 오류를 ERROR 스택 트레이스로 남기지 않는다.
7. **외부 예산의 클라이언트별 몫** — 요청이 부르는 외부 API 는 클라이언트(접속 주소)별로 공급자 일일 한도의
   `QUOTA_CLIENT_SHARE_PCT`(기본 20%)까지만. 요청 수가 아니라 실제 외부 호출을 세므로 캐시 적중 · 화면 자동 갱신은 몫을 쓰지 않는다.
   `ClientContext`(InheritableThreadLocal)라 요청이 띄운 가상 스레드도 같은 몫. 전체 한도 · 몫 · 사용 기록은 Lua 한 번.
8. **캐시 쇄도 방지** — `JsonCache.get` 은 같은 키를 동시에 못 찾은 요청의 불러오기를 한 번으로 합친다.
9. **규모 지표는 추정치 대신 정확한 값 + 측정 시각** — 전체 행 수를 통계 추정치(`pg_class.reltuples`)로 바꾸면 빨라지지만
   화면에 추정치를 내지 않는 원칙(ADR-016)에 어긋난다. 정확히 세되 5분에 한 번만, `measured_at` 을 함께 낸다.
10. **환승 여정 복원 규칙** — CSA 로 찾은 도착에서 거슬러 올라갈 때, 출발 후보역이라도 그 역에 갈 수 있는 시각이 구간 출발보다
    늦으면 그 역에서 탄 것이 아니다 → 도착 경로를 계속 따라간다.

## 결과 (실측)

- 여정 복원: 실제 하루 시간표 × 무작위 출발·도착 3,000쌍 — 탈 수 없는 여정 17건(0.6%, 09-22) · 20건(0.7%, 09-19) → 0건, 도착 시각 동일
- 가상 스레드 고정: `Memo` 에서는 추적 출력 없음
- 성능(A/B, p50): 역 검색 15.5 → 5.6ms · 수집 상태 88.5 → 43.3ms · 철도 화면 첫 로드 231 → 183ms · 분석 화면 첫 로드 JS 약 55% 감소
- 수집기: 60일 재분류의 튀는 값 제거(구간 하나) 13,582 → 14.3ms, 결과 동일

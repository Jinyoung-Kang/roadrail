# ADR-029 도착 시각 기준 판단 — 기차는 30일 실제 지연 빈도로 확률, 자동차는 예측 시각만

- 상태: 채택 (2026-10-10)
- 배경: [명세서](../spec/2026-10-10-arrival-reliability-spec.md) · [설계 계획서](../spec/2026-10-10-arrival-reliability-design.md).
  "14시까지 대전에 가야 한다 — 늦어도 언제 떠나야 하나"에 답한다(AR-1 도착 확률 · AR-2 마지막 출발 시각, AR-3 배상 통계는 앞 PR).
  사용자 결정(2026-10-10): 권장안대로 — 자동차 확률은 오차 모델의 보정 검사를 통과한 뒤에만(D1-A), 배상률은 쓰지 않음(D2-A),
  신뢰 수준 기본 90%(D3), 배상 통계 기본 90일(D4).
- 원칙: 화면 값은 공식 데이터 · 그 값으로 계산한 통계 · 명시한 예측만(데이터 원칙). 확률은 과거 빈도이지 보장이 아니라고 밝힌다.

## 결정

1. **기차 확률 = 경험적 누적분포(규칙 AR-v1).** 같은 열차 · 같은 역 쌍의 최근 30일 검증 운행(계획 시각을 아는 운행) 도착 지연으로
   P(지연 ≤ 여유). 마지막 구간의 여유 = 기한 − 역에서 시간 − 계획 도착, 환승 구간 = 다음 열차 계획 출발 − 앞 열차 계획 도착 − 승차 여유 5분.
   여정 확률은 구간 확률의 곱(독립 가정). 다음 열차의 지연 · 운행 취소는 반영하지 않는다(가정 목록에 그대로 적는다).
   - 모형(정규 · 감마 분포 맞추기)을 쓰지 않았다 — 열차당 표본이 중앙값 24회라 꼬리 모양을 가정하게 되고, 빈도는 화면에 "24회 중 22회"로 그대로 보일 수 있다.
2. **표시 규칙.** 검증 운행 15회 미만이면 퍼센트를 내지 않고 빈도만, 관측된 운행이 모두 기한 안이면 "100%" 대신 "24회 모두 기한 안".
   **신뢰 수준 만족도 15회 이상일 때만** — 10회 모두 기한 안이어도 95% 신뢰 하한은 약 72%라 "90% 만족"이라 하지 않는다(실데이터에서 10회짜리
   환승 여정이 만족으로 뽑히는 것을 보고 정했다). 만족하는 후보가 없으면 기록이 충분한 것 중 확률이 가장 높은 후보, 그것도 없으면 가장 늦은 후보를
   `meetsConfidence=false` 와 이유와 함께.
3. **지연 기간은 운행 기록의 가장 최근 30일.** 시간표 기준일(같은 요일 최근 운행일, 평일엔 공휴일 제외)은 추석 · 개천절이 낀 주에는 3주 전(09-19)까지
   밀려, 그 날까지의 30일을 쓰면 최근 3주의 지연을 놓쳤다(실측: 서울→대전 265 열차 19회 → 24회). 시간표는 기준일, 지연 분포는 최근 30일로 나눈다.
4. **마지막 출발 시각 — 거꾸로 찾는 CSA.** `RailRouter.latest`: 연결을 출발 시각 내림차순으로 훑으며 역마다 '여기서 떠나 기한 안에 닿는 가장 늦은 출발'을
   갱신한다(같은 열차 계속 타기는 벌점 없음, 갈아타기는 최소 환승 10분). 후보 역 · 역까지 시간 · 오늘+내일 시간표 · 실제 시간표 재확인은 앞으로 찾기(`plan`)와
   같은 코드를 쓴다. 집 출발이 늦은 순으로 6개를 뽑아 실제 시간표로 다시 보고, 역까지 시간은 짐작한 출발(기한 − 거리 ÷ 100km/h − 60분)로 구한 뒤
   실제 출발과 30분 넘게 다르면 그 시각으로 다시 구한다(카카오 단일 경로만 — 다중 길찾기는 시각과 무관).
5. **자동차는 카카오 미래 운행 정보로 10분 단위 마지막 출발만, 확률 없음(D1-A).** `LatestDeparture.search`: 짐작한 출발에서 시작해 늦으면 넘친 만큼 앞당기고,
   맞으면 한 칸씩 늦춰 본다. 요청당 카카오 호출 4번 이하(공유 예산 · 20분 캐시). 카카오 출발 시각이 10분 단위라 명세의 5분보다 거칠다.
   카카오 예측과 고속도로 실측의 비율이 한쪽으로 치우쳐(중앙값 1.175, 추석 포함 기간 · 같은 시각 구간 합) 궤적 합으로 정답 데이터를 만든 뒤 판단한다(3단계).
6. **응답이 늦으면 pending.** 카카오 · 시간표가 아직 오는 중이면 `pending=true` 로 캐시하지 않고 화면이 1.5초 뒤 다시 묻는다(판단 카드와 같은 규칙).
   자동차는 새 10분 칸을 물을 때마다 한 번씩 pending 이 날 수 있다 — 실측 3~4번 안에 수렴하고 그 뒤 60초 캐시.

## 보정 검사 (출시 조건 ±5%p)

`make arrival-calibration`(`tools/arrival_calibration.py`, DB 읽기만) — 날짜 d 의 운행을 [d−30, d−1] 기록만으로 예측해, 여유 0 · 2 · 5 · 10 · 15 · 20 · 30분마다
예측 p 와 실제 적중을 비교한다. 2026-10-10 실행(평가 07-24 ~ 10-08):

| 데이터 | 평가 운행 | Brier | p 0.80–0.90 (예측 → 실제) | 0.90–0.95 | 0.95–1.00 | 모두 기한 안(p=1) |
|---|---:|---:|---|---|---|---|
| A. 전국 종착역 도착 | 63,111 | 0.067 | 0.843 → 0.838 | 0.923 → 0.925 | 0.965 → 0.971 | 0.991 |
| B. 주요 6개 역 쌍 | 19,287 | 0.085 | 0.843 → 0.824 | 0.923 → 0.921 | 0.964 → 0.969 | 0.987 |

모든 구간이 2%p 안팎으로 맞고, 80 · 90 · 95% '만족' 판단의 실제 적중률은 0.96 ~ 0.99(기준 c − 5%p 통과). 'p = 1'의 실제 적중이 0.99 라
"100%"라고 쓰지 않는 규칙이 맞다. **환승 여정(독립 가정)은 아직 재지 않았다** — 같은 날 지연이 겹치면 실제보다 높게 나올 수 있어 화면 가정 목록에 적었다.

## 3단계 — 자동차 확률의 정답 데이터 (2026-10-10)

- **궤적 합(규칙 T-v1)** `collector/roadrail/analytics/trajectory.py`: 원천 슬롯은 도착(진출) 기준이라, 구간 i 에 τ 에 들어간 차의 소요 s 를
  s = 값(floor5(τ + s)) 의 고정점(최대 4번)으로 찾고 다음 구간은 τ + s 에서 시작한다. 값은 1종 · 품질 OK · 튀는 값 제거(H-v1) 뒤, 없으면 ±10분 안
  가장 가까운 슬롯, 그것도 없으면 계산하지 않는다(정답에 추정을 섞지 않음 — 길 합산의 24시간 중앙값 · 자유속도 채우기를 쓰지 않는다).
- **V19 `ana.kakao_eta_eval`** + 매일 04:55 작업 `kakao_eta_eval`(최근 7일, 출발 뒤 8시간 지난 것만, 외부 호출 없음). 카카오 예측 원본은 90일 보존이라
  예측 소요를 함께 둔다. 첫 채우기(10-10): 예측 1,648건 중 285건 — 나머지는 스택이 꺼져 있던 기간 · 원천 결측으로 구간 값이 없었다.
- **보정 검사(`make arrival-calibration` C절)**: 정답 기간 28일 이상 · 시간대 × 휴일 칸 표본 50 이상일 때만 마지막 14일로 판정한다.
  지금은 11일(관측일 5일) · 모두 휴일(추석 · 주말 · 개천절)이라 **보류 — 자동차 확률은 화면에 내지 않는다**(D1-A 그대로).
  궤적 합을 정답으로 쓰자 비율(실제 ÷ 카카오) 중앙값이 같은 슬롯 합의 1.175 에서 1.079 로 줄었다(p10 0.875 · p90 1.386) — 같은 슬롯 합이 정체가
  쌓이는 동안의 소요를 과장한 몫이 있었다. 통과하면 API 의 `car.odds` 와 화면을 여는 작업을 따로 한다.

## 결과

- API `GET /api/v1/trip/arrival`(기한 지금+30분 ~ 24시간 · 5분 내림, 신뢰 수준 0.8 · 0.9 · 0.95, 60초 캐시 — `trip` 요청 한도).
  domain `DelayDistribution` · `ArrivalOdds` · `LatestDeparture` · `RailRouter.latest`, rail/data `delaySamples`, trip/app `ArrivalService` · `RailJourneyService.latestPlan`.
- 웹: 판단 화면에 `판단 기준`(출발 · 도착 시각) 라디오 그룹, 도착 기준이면 날짜 · 시각(5분) · 신뢰 수준, 주소 `?by=arrive&d=&at=&c=`. 카드 두 장 "늦어도 HH:mm 출발".
- 실데이터(10-10): 서울역 → 대전역 14:00 기한 — 기차 12:33(KTX 265, 24회 모두 기한 안), 자동차 11:40(예측 2시간 18분), "기차로 가면 53분 늦게 떠나도 됩니다".
- 하지 않은 것: 환승 여정 보정 · 지연 상관 반영, 평일 · 주말 나누기, 자동차 확률(3단계), 역까지 시간의 불확실성.

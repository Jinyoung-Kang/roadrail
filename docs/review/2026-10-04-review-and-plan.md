```
corridor/  web · app(CorridorService · NowCardService · RoadService · 길 매칭) · data · model

```

1. 순수 이동(동작 불변): `web.dto` 레코드 → 각 기능 `model` (지금 서비스 → 웹 계층 의존 23곳 제거), common/config → shared, 컨트롤러 · 서비스를 기능 패키지로.
2. 작은 코드 변경: 서비스끼리 빌려 쓰던 정적 도우미(`TripService.join/left`, `RoadService.ptyName`, `EnvService.skyName`, `RailService.round`)를 shared · domain 으로, `TripService.observed()` → 길 매칭.
3. SQL 을 기능별 `@Repository` 로(철도 25문장 → 환경 → 도로). 인터페이스는 만들지 않는다(구현이 하나뿐). OpsService 는 조회 전용이라 그대로.
4. 의존 방향을 지키는 테스트(새 의존성 없이 import 검사): app 은 web 을, domain 은 바깥 계층을 import 하지 않는다.

**프론트엔드** — 화면과 로직 분리.

1. 색 · 지도 타입을 한곳(`lib/palette` · `lib/map`)으로(지금 `lib/layers` 가 컴포넌트를 import — 역방향).
2. `lib/api/client.ts`(React 없음: `getJson` · 엔드포인트 URL 생성 · `runJob`) + `lib/hooks/useApi.ts`(요청 취소 · `isStale` · 숨긴 탭 멈춤 · 재시도 상한). SWR 등 새 라이브러리는 쓰지 않는다.
3. 순수 함수 모듈 + 테스트: `lib/trip` · `lib/road` · `lib/rail` · `lib/ops`.
4. 페이지 훅: `usePlaceQuery` · `useTrip` · `useRailOd` · `useCorridorParams` · `useAdminToken` · `useKakaoMap/useMapLayers` · `useDebouncedSearch`.
5. `components/Tiles.tsx`(439줄 · 컴포넌트 12개) → `components/trip/*` 로 나눔.

**런타임**: Node 22 → 24 LTS(웹 이미지 · CI), Python 3.11 → 3.13(수집기 이미지 · CI · `requires-python`). 결정은 ADR 로.

**검토**: 전체 변경을 처음 보는 리뷰어 입장으로 따로 검토(별도 에이전트) → 정확성 · 요구사항에 영향을 주는 것만 고침.
